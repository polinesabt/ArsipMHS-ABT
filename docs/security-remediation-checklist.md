# Tindakan produksi setelah patch lokal ditinjau

Dokumen ini adalah daftar kerja manual. Jangan jalankan probe GET ke file PHP perawatan pada situs live.

1. **Tahan paparan sebelum restore:** unggah `backend/.htaccess`, `backend/vendor/.htaccess`, dan `backend/storage/.htaccess`; verifikasi dengan file uji yang tidak menjalankan operasi database. Hapus folder `public_html/backend/scripts`, `public_html/backend/database`, dan `public_html/backend/database productin ekspor` dari hosting setelah memastikan tidak ada tugas CLI yang bergantung pada lokasi tersebut.
2. **Pulihkan dan audit data:** simpan bukti/log insiden, restore database dari backup sebelum 7 Oktober 2026 17:10 WIB ke salinan terisolasi, bandingkan jumlah data mahasiswa dan tabel terdampak, lalu jadwalkan restore produksi. Periksa tambahan data contoh yang mungkin tercipta dan hapus tabel `uji_agent` hanya setelah verifikasi backup.
3. **Tutup kebocoran kredensial:** ganti password admin melalui CLI `bootstrap-admin.php` dengan `ADMIN_BOOTSTRAP_PASSWORD` baru, reset password semua akun yang hash-nya ada di dump, ganti `JWT_SECRET` produksi agar token lama tidak berlaku, dan nonaktifkan akun demo. Jangan taruh password atau hash baru di SQL/repo.
4. **Bersihkan repositori:** hapus seluruh dump produksi yang masih terlacak, termasuk `backend/database productin ekspor/*.sql`, `backend/database/production_full_migration_with_backup_data.sql`, `backend/database/production_schema_update_latest.sql`, dan salinan migrasi berisi data nyata. Jadikan repo private, bersihkan riwayat Git dan cache publik, lalu periksa ulang secret scan. Membuat repo private saja tidak menarik kembali salinan yang telah diunduh.
5. **Siapkan deploy:** pastikan migrasi izin admin `2026-08-15-add-admin-permissions.sql` dan kolom soft delete mahasiswa sudah diterapkan. Jalankan `2026-10-07-login-rate-limit.sql`, `2026-10-07-students-list-index.sql`, dan `2026-10-07-disable-demo-accounts.sql` di staging, lalu produksi saat jadwal deploy. Jangan jalankan migrasi `2026-09-12-remove-demo-and-reset-admin.sql` yang belum ditinjau; migrasi itu juga menghapus akun admin lain. Set `APP_ENV=production`, `JWT_SECRET` acak minimal 32 karakter, dan `ALLOWED_ORIGIN=https://arsipmhs-abt.com`. Deploy GitHub Actions kini hanya dapat dijalankan manual melalui `workflow_dispatch`, setelah langkah ini selesai.
6. **Verifikasi setelah deploy:** semua pengguna login ulang. Uji `403/404` untuk file statis sensitif, `401/403` untuk akses API tanpa izin, alur admin/mahasiswa, lampiran melalui endpoint API, ekspor, serta p99 dan error rate pada staging. Jika PHP/MySQL shared hosting masih jenuh, tingkatkan kapasitas hosting setelah metrik terukur.

Push kode tidak menjalankan migrasi database atau deploy produksi. Tindakan hosting, database produksi, rotasi kredensial, dan pembersihan riwayat Git tetap perlu dilakukan terpisah.
